Today's Lesson

Programmatic tool calling: let the model write the loop

In a classic agent loop, every tool call is a round trip: the model emits a call, the harness runs it, the result is appended to context, and the model is invoked again. Ten calls means ten model invocations, each re-reading a growing prefix, and every raw tool result lands in the context window whether or not the model needed all of it.

Programmatic tool calling (what Pi's Codemode does) flips this. The model writes one short script that calls several tools, loops over results, filters, joins and branches, and only the final distilled output returns to context. Independent calls can run in parallel, and intermediate data such as a 5,000-row query result never gets tokenized.

The wins are fewer model turns (lower latency and less re-sent context), fewer tokens, and more reliable control flow, since loops and conditionals are code rather than sampled text. The costs: you now run model-written code, so the sandbox, permissions and egress limits matter a great deal, which ties directly into this week's agent-containment stories. Also, when a tool returns structured data, a script can consume it directly, which is why MCP servers that return typed results compose better.

Rule of thumb: if a task is "call N things and combine them," write code; if each step depends on judgment about the last, keep the loop.
