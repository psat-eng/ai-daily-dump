Stealing Reasoning Traces from Frontier APIs — and it worked until they patched it
Aug 11·stolen-thoughts.com / simonwillison.net

A paper dropped this week (arXiv:2608.09867) showing that Anthropic, OpenAI, and Google all used the same encryption key family-wide for encrypted reasoning traces. Researchers could take a trace from a stronger model, replay it into a weaker sibling, and trick it into outputting the raw chain-of-thought in plaintext. Claude Haiku 4.5 was the easiest to crack: prefill <thinking-copy> + ask it to transcribe verbatim.

Particularly nasty variant: you could seed a model's encrypted thinking trace with instructions for data exfiltration, then replay that trace into another model — which would follow through because models treat their own reasoning as authoritative. All three providers have since patched it, and the paper notes the attack no longer works. The extracted traces are a fascinating peek at what raw frontier reasoning actually looks like (spoiler: stream-of-consciousness fragments, not tidy prose).

Claude Code auto mode goes default tomorrow (Aug 14) for Pro/Max/Team
Announced Aug 8, effective Aug 14·Anthropic

Starting tomorrow, Claude Code auto mode becomes the default permission model for new sessions on Pro, Max, and Team — Enterprise and API users stay opt-in for now. Auto mode bypasses per-action approval prompts unless an action is "irreversible, destructive, or aimed outside your environment."

The data behind this is compelling: in a 1,053-person study, humans only caught 13.6% of deliberately-injected dangerous commands vs. 89% for auto mode — confirmation fatigue is real. Anthropic also commissioned Trajectory Labs to test 720 indirect prompt injection attempts against Claude 5 models running auto mode: zero succeeded. Simon Willison remains skeptical on edge cases (e.g. malicious packages instructing the model to fetch and execute something), which seems fair.

📚 Also Worth Reading
AI4AI at Test-Time: Strong-to-Weak Capability Transfer via Harnesses (#1 paper on HF today)
Aug 13·UIUC / Hugging Face Papers

Today's top Hugging Face paper asks: can a strong model transfer its capabilities to a weaker one at inference time, without any training? Answer: yes — and it nearly doubles performance. The trick is having the strong model build inference-time "harnesses" for the weak model: structured code that enforces output format, deterministic routing for sub-tasks, and benchmark-specific scaffolding. The gains come from offloading unstable model reasoning into code, not from getting the weak model to think harder. Weaker target models benefit the most. Relevant for anyone designing multi-agent pipelines with mixed model tiers.

📖 Today's Lesson
Speculative Decoding: how inference servers get 2–4× throughput for free

LLM inference is memory-bandwidth bound, not compute bound. During each decoding step, the model reads all its weights from VRAM to generate a single token — which means GPUs are mostly waiting on memory transfers, not doing math. Speculative decoding exploits this idle compute.

The idea: pair a small "draft" model (e.g. 1–7B) with your large "target" model (e.g. 70B+). The draft model autoregressively generates 4–8 candidate tokens speculatively. The large model then evaluates all of those candidates in a single forward pass — because the target can process multiple tokens in parallel via its attention mechanism, even though it can only generate one at a time. If the draft tokens match what the target would have generated, you accept them all. If one diverges, you reject from that point and re-draft.

In practice, acceptance rate depends on how well the draft matches the target's distribution. For repetitive or predictable text (code, structured output, long repeated patterns), acceptance rates of 70–85% are common, giving 2–4× effective throughput at the same output quality. For highly creative or unpredictable text, it degrades toward 1×.

Modern serving stacks handle this automatically: vLLM has built-in speculative decoding, llama.cpp's --draft-model flag does the same, and Ollama's MLX engine now uses MTP heads for speculative decoding automatically when the model supports it (as of 0.32.7). The "draft model" can even be a self-speculative variant — using early layers of the same model, trading quality for zero extra VRAM.
