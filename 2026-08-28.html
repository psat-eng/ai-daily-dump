Today's Lesson
Prefix Caching: Free Tokens on Every Repeated Prompt

Every time you call an LLM API, the model runs through your prompt token-by-token to build up the Key-Value cache before it generates the first output token. Prefix caching skips that work when you've sent the same prefix before.

Here's how it works: the inference engine hashes the token sequence of your prompt prefix. If that hash matches a previously computed KV cache block that hasn't been evicted, it reuses it — your TTFT drops dramatically and you pay nothing for those input tokens (on APIs that pass savings through, like OpenAI's prompt caching or SGLang's radix attention). A cache miss means a full prefill as normal.

The practical win is largest when you have a long, stable prefix. A 4,000-token system prompt that stays constant across requests? After the first call, subsequent requests hit the cache and pay only for the user-turn tokens. Few-shot examples, tool definitions, retrieved documents that are the same across a session — all cacheable.

Architecturally, vLLM implements this via enable_prefix_caching=True in its engine args; SGLang calls the same idea RadixAttention and makes it the default. Both use a radix-tree structure to share KV cache memory across requests with common prefixes, not just identical full prompts. That means partial matches (different user turns on the same system prompt) get cache hits on the shared prefix portion.

Tie to today: OpenAI's GPT-5.6 Sol price cut drops input to $4/1M tokens. With prompt caching, repeated system prompt tokens are charged at a discounted cache-hit rate (typically 50–75% off). On high-throughput agent loops with a fixed 2,000-token system prompt, the effective cost per call can be closer to $1/1M on the prompt portion — before you've done any other optimization.
