🔥 What's Hot Right Now
GLM-5.3-Flash drops — and it's Ox Alpha
HuggingFace weights · Z.ai announcement · r/LocalLLaMA megathread · HN #12, 354 pts · Released today
Z.ai confirmed it: Ox Alpha = GLM-5.3-Flash, and the weights are live under MIT. The model runs entirely on Chinese AI chips. Numbers: 320B total parameters, 18B active per token.

Architecture: 45 layers in repeating blocks — 3× KDA linear attention followed by 1× DeepSeek-style sparse attention (34 linear / 11 sparse total). The sparse layers use a "lightning indexer" with a top-k budget of 2048 tokens, sharply cutting long-context serving cost vs. full attention.

Natively multimodal: a 24-layer ViT (448px, patch 14, 2×2 spatial merge) with temporal patching handles both image and video tokens natively — trained on a 30T-token multimodal corpus. 1M token context window.

MTP head ships in the weights: one next-N prediction layer is baked into the checkpoint. The official vLLM recipe uses it with k=5 speculative tokens out of the box. (See today's lesson for how this works.)

FP8 by default, with a separate BF16 repo. Z.ai's pitch: outperforms GLM-5.2 at one-tenth the price, approaching Claude Opus 4.8 on coding and agentic benchmarks.
Qwen3.8-Flash-Next: a live preview of the Qwen4 architecture
qwen.ai blog · HuggingFace weights · HN #13, 360 pts · Released today
Alibaba's Qwen team shipped Qwen3.8-Flash-Next today — explicitly framed as an architectural preview of Qwen4, released early so tool builders and quantizers can adapt before the full family lands. Numbers: 125B total parameters, 6B active per token (MoE), 262K native context extendable to 1M.

Two headline changes: GDN hybrid architecture (upgraded attention, residual, embedding and optimization paths) and Qwen Sparse Attention (QSA), their own take on sliding-window + top-k sparse attention for long-context cost reduction. Training cost vs Qwen3.7-Plus: about 1/9th, with better coding and office task benchmarks.

Unsloth GGUF quants are already up. Worth benchmarking against GLM-5.3-Flash — two large MoE architecture previews in one day is unusual.

📖 Today's Lesson
MTP Heads: How Models Become Their Own Draft Models for Speculative Decoding

Standard speculative decoding requires a separate small "draft" model that proposes k tokens, which the main model verifies in a single parallel forward pass. The friction: you need to load, serve, and schedule that draft model independently, and if the draft model is too architecturally different, acceptance rates drop.

Multi-Token Prediction (MTP) heads solve this by baking the draft model directly into the checkpoint. During training, lightweight auxiliary prediction heads are attached after the final transformer block — one per speculative position. Each head learns to predict token at position +n using a small MLP on top of the shared hidden states. At inference, these heads run on the same forward pass that already computed the main model's next-token logits, producing draft tokens essentially for free — no extra KV cache, no separate batch queue.

The main model then verifies all k proposals in one speculative step and accepts the longest valid prefix. DeepSeek-V3 popularized this pattern; GLM-5.3-Flash ships one MTP head today, and the official vLLM config uses it with speculative_tokens=5 out of the box.

The gotcha: longer speculative chains hurt at long context. GLM's benchmarkers found k=7 drops throughput from 76 to 55 tok/s at 65K tokens — verification cost grows faster than draft gains. Rule of thumb: use k=3–5 for typical workloads, drop to k=2–3 when serving long-context requests. Tune per deployment, not globally.
