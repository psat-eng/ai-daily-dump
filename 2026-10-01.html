Today's Lesson

Classify by scoring tokens, not generating them

Many agent decisions are multiple choice: run the tool or not, which of five routes, is this document relevant. The naive way asks the model to write an answer, then parses it. That wastes decode steps, invites formatting errors, and costs latency.

A cheaper trick: run one forward pass over the prompt and read the logits at the final position for just the allowed answer tokens (say "yes" and "no", or "A" through "E"). Softmax over that small set gives a probability for each option, so you also get a confidence score for free. Decoding is skipped entirely: one prefill, no output loop.

That is the idea behind today's Strands Decider 2B, which scores the allowed answers directly. The Quail paper (Sep 24, on Hacker News this week) uses a similar shortcut for AI-SQL filters, computing only TRUE/FALSE token scores instead of a full-vocabulary output projection, and it also reuses the anchor document's KV cache across join comparisons.

Practical notes: put the options in a fixed format, use a threshold on the probability to escalate unsure cases to a bigger model, and calibrate on labelled examples, since raw token probabilities are often overconfident. Prefix caching makes it cheaper still when many questions share one long context.
