Historic Multi-Agent Claude formalizes Fermat's Last Theorem — 11 days, 13M lines of Lean, fully machine-checked
Anthropic announced today that Claude produced the first complete, computer-verified proof of Fermat's Last Theorem. Running largely autonomously for 11 days on the Prove2Me collaborative formalization platform, a multi-agent Claude Code system generated 13 million lines of Lean code and proved 29,500 intermediate theorems — more than five times the size of Mathlib. The final proof was verified using Lean's three standard axioms with no additional assumptions. Total compute: roughly 6 billion output tokens from an internal model comparable to Fable 5.1. Human input was limited to occasional high-level steering ("push the Mazur theorem to be done soon"). Imperial College London's Kevin Buzzard confirmed it proves FLT "with no assumptions other than the axioms of mathematics." A separate experiment formalized Vinogradov's Three Primes Theorem in just 3 days using three Claude Max plans. The full proof and a written walkthrough are on GitHub.

📖 Today's Lesson
Token Budget Management in Agent Loops: How to Think About 6 Billion Output Tokens

Today's Fermat proof consumed roughly 6 billion output tokens over 11 days. That's not a typo. At Fable 5.1 pricing ($50/M output), that's around $300,000 in inference — for one math proof. It raises a question every inference engineer working on long-horizon agents needs to answer: how do you actually manage token budgets in a multi-agent loop?

A few key concepts:

Output vs input asymmetry. Output tokens cost 5–10× more than input tokens and are the primary driver of agent cost. A loop that generates verbose intermediate reasoning steps or writes long tool call payloads will blow up fast. Caching repeated context (like a shared codebase or proof state) as prompt cache hits is the single highest-leverage lever on input cost.

State externalization. The reason earlier Claude attempts on FLT failed was agents losing project state. The fix (Prove2Me) was essentially an external state store — agents read/write structured proof state rather than carrying everything in context. This is the standard pattern for long-horizon work: context windows are ephemeral; your state store is not. Think of it like redis for agent memory.

Budget allocation across agents. In a multi-agent system, you want a lightweight orchestrator that tracks overall progress cheaply, and expensive worker calls that only happen when needed. Routing easy subtasks to smaller models (or skipping LLM calls entirely for deterministic checks like Lean's type checker) can cut cost by an order of magnitude. The FLT team's use of Lean as an external verifier meant agents didn't need to self-verify correctness — the proof checker did it for free.

Practical rule of thumb: before running a long agent loop, estimate your worst-case token count. If the answer is "I don't know," that's the first thing to fix.
