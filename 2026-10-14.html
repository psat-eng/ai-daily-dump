Janas: a C engine that streams MoE experts from SSD to run 80B models on a 32 GB laptop

Weights stay on NVMe; the experts each token needs are streamed in while hot experts stay cached in RAM. The author reports 20–25 tok/s on Qwen3-Next-80B-A3B and ~32 tok/s on Qwen3.6-35B-A3B, with multi-token-prediction drafts verified by the model so output should match non-speculative decoding. Caveats from the README: it was tested on a single Intel Core Ultra 9 laptop with a ~5.7 GB/s SSD, it is labelled experimental, and it can push a desktop into swap. 219 points on HN.

🧠 Today's Lesson
Speculative decoding: why drafted tokens don't change the output

Janas says its multi-token-prediction drafts are "verified by the model", so output should match what the model would have produced anyway. That property is the core idea of speculative decoding, and it is why the technique is a pure speed-up rather than a quality trade.

Decode is slow because each token needs one full pass over the weights, and that pass is limited by memory bandwidth, not arithmetic. A GPU (or a laptop streaming experts from SSD) has spare compute during that pass. Speculation spends it: a cheap draft mechanism, either a small model or extra prediction heads on the main model, guesses the next k tokens. The big model then scores all k positions in a single forward pass, which costs about the same as generating one token because the weights are read once.

Verification compares the draft to what the big model would have chosen. Under greedy decoding, the first mismatch is replaced by the big model's token and the rest are discarded. Under sampling, a rejection-sampling rule accepts or resamples each drafted token so the final distribution is mathematically identical to ordinary sampling. Either way each pass yields at least one real token, and up to k+1 when the guesses are right.

The speed-up depends on the acceptance rate. Predictable text such as code boilerplate and JSON accepts often; high-entropy prose less so. A bad draft model costs time without changing answers. That is why vLLM v0.31.0's draft-model support matters for serving, and why it pays most when the bottleneck is bandwidth, as it is for SSD-streamed MoE experts.
