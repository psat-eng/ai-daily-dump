Tool · Nov 8-9 · 242 GitHub stars
Flide, an open-source inference engine for "decision models," ships three releases in two days

The Apache-2.0 project describes itself as fast inference infrastructure for Jev-style decision models, serving a /v1/systemone API that takes a state plus several typed questions (choice, yes/no, score) and answers them in one call. Using exact state forking, the README claims up to 9.5x lower latency than vLLM and SGLang on one H200, with each answer identical to what the model gives the question alone.

Version 0.1.8 (Nov 8) added several decision-model families, 0.1.9 (Nov 9) added Perplexity's pplx-decider-v1.1-27b and batched requests in one body, and 0.1.10 (Nov 9) added image input for the KnowLine family. Speed figures are the project's own.

Tool · Nov 5 · 4 days old
inferd v0.4.1: a from-scratch Apple Silicon engine built for many concurrent agents

The repository describes a C++/Metal engine with continuous batching, per-agent speculative decoding, an 8-bit paged KV cache, a prefix cache that hands one agent's context to the next, and an SSD tier for contexts that do not fit in memory. Its README reports 64 agents on one Mac Studio (M5 Ultra) at 849 tok/s on Qwen3.8-27B with 16k contexts each, and states plainly that other engines remain faster for a single stream. The author calls it young, experimental software.

🛠️ Flip Tech Watch
Flip Tech Watch · Nov 8-9
Flide: serving decision models that answer many classification questions in one call

The README's example is a customer-support case: a state describing a cracked-screen order with photos, plus a "what should support do next?" choice question (refund, replace, escalate) and a yes/no urgency question, answered in one request. It lists the supported model families with latency comparisons against vLLM and SGLang, and installs with uv pip install flide.

Flip angle: Intent routing and escalation-reason tagging on calls could be served as a batch of typed questions per transcript rather than separate generation calls, with probabilities usable as confidence thresholds for hand-off to a live agent. The speed-ups are self-reported on an H200 and on the project's own workloads; the first test is replaying a day of labelled escalated calls and comparing agreement with current intent labels and p95 latency.

Flip Tech Watch · Nov 8
Artificial Analysis publishes Decision Index v2 for decision models

The index combines six evaluations covering document decisions and extraction, workplace-document judgement, tool calling (When2Call), knowledge and hallucination, reasoning, and a symmetry check that a decision holds when a question is reordered, relabelled or negated. Scores reward calibration: accuracy less the Brier score of the chosen answer's probability. AI Weekly's summary reports Nace AI's Drex Max v1.1 and Fastino's GLiDE v1.2 tied at 73, with Base Labs' Mammoth 27B at 72.

Flip angle: It gives a neutral shortlist and a cost-per-million-tasks view for models that could handle intent classification and "should this escalate?" decisions. The benchmark tasks are documents and generic support-style questions, not voice transcripts, so the useful step is scoring two or three shortlisted models on Flip's own labelled call set, including a calibration check on escalation confidence.

🧠 Today's Lesson
Calibration and the Brier score: why "80% sure" should be right 80% of the time

A classifier that returns a label is only half useful; one that returns a probability can be thresholded, routed and audited. But a probability is only meaningful if it is calibrated: across all the cases where a model says 0.8, about 80% should turn out right. Many models are overconfident, saying 0.95 on cases they get right only 70% of the time.

The Brier score measures this. For each prediction, take the squared gap between the probability assigned to the outcome and what happened (1 if it occurred, 0 if not), then average. A confident wrong answer (0.95 on something false) costs about 0.90; a hedged wrong answer (0.6) costs 0.36; a confident right answer costs almost nothing. Unlike plain accuracy, it punishes confident mistakes and rewards honest uncertainty. Artificial Analysis's index uses "accuracy less Brier" for this reason.

For a voice-agent stack the payoff is operational. If intent confidence is calibrated, a rule like "escalate to a live agent below 0.7" has a predictable error rate; if it is not, the threshold is a guess. A quick check is a reliability table: bucket predictions by confidence (0.5-0.6, 0.6-0.7, and so on) and compare each bucket's average confidence to its actual accuracy.
