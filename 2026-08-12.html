Claude Code auto mode becomes default August 14 — no more permission prompts for most actions
Starting Thursday, new Claude Code sessions on Pro, Max, and Team plans run in auto mode by default. In auto mode, Claude proceeds without asking unless an action is deemed irreversible, destructive, or outside the user's environment. A small classifier runs per tool call to make that determination — Anthropic is not charging for that classifier overhead. Internal testing: auto mode detected 89% of harmful actions; human review (the current default) only caught 13.6%. 📖 Today's Lesson
AWQ vs GPTQ vs GGUF: picking the right quantization format when downloading community models

When you pull a community model from Hugging Face, you'll almost always see multiple quant variants. All three formats reduce model precision from 16-bit floats to lower bit-widths (2–8 bit), but they make different tradeoffs around where and how they compress.

GGUF (successor to GGML, used by llama.cpp, Ollama, LM Studio) is the format for CPU-first or CPU+GPU hybrid inference. Weights are stored in a single portable file with built-in tokenizer metadata. The quantization can be applied per-block with mixed precision (e.g. Q4_K_M applies 4-bit to most layers but keeps sensitive layers at 6-bit). Q4_K_M is usually the community sweet spot: ~4.5-bit average, minimal quality loss, fits a 7B model in ~4GB. GGUF's design goal is portability — one file, any machine.

GPTQ is GPU-native quantization that runs a calibration pass over a small dataset (typically WikiText-2) to find the optimal rounding per weight, minimizing the reconstruction error layer by layer. It's deterministic given the same calibration set but takes hours to compute. The result is a weight-only quantized model that loads natively into transformers or auto-gptq. GPTQ shines on CUDA GPUs where you want quantized weights but full-speed matmuls — it uses triton kernels to dequantize on the fly. Downside: no CPU support, and calibration set choice can affect quality unpredictably.

AWQ (Activation-aware Weight Quantization) is GPTQ's smarter sibling. Instead of minimizing weight reconstruction error in isolation, AWQ identifies which weight channels matter most by looking at actual activation magnitudes, then scales those channels to protect quality before quantizing. It doesn't need a calibration dataset and is generally faster to compute than GPTQ. The resulting quality at 4-bit is often slightly better than GPTQ, especially for instruction-following tasks. AWQ is the preferred format for GPU-only serving in vLLM and SGLang.

Rule of thumb: CPU or hybrid inference → GGUF. GPU-only production serving → AWQ (first choice) or GPTQ. When downloading community quants, prefer AWQ or Q4_K_M GGUF and avoid Q2 variants unless you're memory-constrained enough that the quality hit is acceptable.
