Acquisition · Oct 29
Deepgram acquires Daily, maker of open-source Pipecat

Deepgram announced on Oct 29 that it is acquiring Daily, the company that builds and maintains Pipecat, a widely used open-source framework for connecting speech recognition, language models and speech synthesis into voice agents. Terms were not disclosed. Deepgram says Pipecat stays open source under the BSD V2 license, with an independent Pipecat Foundation being established; co-founder Kwindla Hultman Kramer joins Deepgram as Head of Open Source.

Deepgram also introduced the Real-Time Context Standard (RCS), an open protocol co-developed with Pipecat that carries audio context such as tone across model handoffs, and cites Daily's WebRTC network of 75 points of presence. Pipecat already shipped native Deepgram speech-to-text and text-to-speech services, so the deal places the orchestration layer and the models under one company. Crypto Briefing reports it follows Deepgram's $130 million Series C in January and its purchase of restaurant voice-AI company OfOne.

Benchmarks · Oct 28 · 103 points on HN
Gemini 4 Carbon is the new #1 on the Artificial Analysis Intelligence Index v5

Artificial Analysis (AA) scores Google's Gemini 4 Carbon (high reasoning) at 59 on Intelligence Index v5, ahead of Claude Opus 5.5 (58) and GPT-6 Astra (57). Carbon takes first place on four of the nine evaluations (HLE-Diamond, Terminal-Bench-Science, AA-Omniscience and AutomationBench-AA). It is not publicly available yet: Google is rolling it out to selected users with a 50% launch discount and no confirmed end date.

On AA's numbers, Carbon costs $7.76 per index task at standard pricing of $4/$20 per million input/output tokens, about 23% below Opus 5.5 (max) at $10.04, and uses 123k output tokens per task versus 173k. Its AA-Omniscience score is 54 with an 11% hallucination rate, up from 4% for Gemini 4 Argon. In AA's Coding Agent Index it scores 59 with Antigravity CLI, three points behind Claude Code with Opus 5.5 (62). Context window is 1M tokens, with cached input at a 95% discount.

Experiment · post dated Oct 22 · on HN front page Oct 29 · 594 points
Qwenputer: a fully functioning, deterministic RISC-V CPU inside Qwen3.5

Divyansh Agrawal compiled a 32-bit RISC-V core (RV32IM) into the weights of a stock Qwen 3.5 4B, adding 11 layers in front of the original 32 and leaving Qwen's own weights unchanged. The model's Gated DeltaNet layers serve as the CPU's RAM: with the gate and write strength set to 1 and one-hot keys, each write overwrites exactly one state row and each query reads it back exactly. No training is involved; a compiler sets the weights directly.

The author reports passing the official riscv-tests, matching qemu, and 18 million free-running instructions without error. On DeepMind arithmetic sets Qwenputer scores 97.5% on div_big and mul_big, against 72.5% and 55% for base Qwen, and on NUPA long-integer arithmetic it goes from 48.6% to 100%, matching Qwen given a Python tool. The post is a week old but only reached Hacker News's front page on Oct 29; weights are on Hugging Face and ModelScope.

Tooling · Oct 29 · 479 points on HN
Claude Code burns ~15–20% of tokens on a 3-word status line

A gist by Flamerix AI says that every ~30 seconds, Claude Code sends each background agent's whole transcript to that agent's own model (usually Opus) to produce a 3–5 word status for the agents panel, and that this has been on by default since version 2.1.232 with no setting to disable it. Using OpenTelemetry query_source grouping, the authors report that agent_summary accounted for 16.4% of Claude Code spend and 19.7% of API requests in the week before their fix, against 15.7% for the main conversation, and cite an issue (#86879) collecting four independent measurements of 18–26%.

The workaround is an ~80-line Bun preload that suppresses the summarizer timer without modifying the binary. These are the authors' measurements on Linux builds 2.1.257–2.1.312, and an update can silently undo the patch.

Open weights · Oct 27 · 2 days old
Introducing LFM3: Every Modality for Specialized Intelligence

Liquid AI released the LFM3 family on open weights: six 2B-class models (text, vision, audio, omni and decision) built from LFM3-1.7B-Base, pre-trained on 22T tokens. The architecture mixes 13 gated short-convolution layers, 5 sliding-window attention layers (256-token window) and 6 global attention layers. Liquid says LFM3-1.7B outperforms the earlier LFM2.5-2.6B with 35% fewer parameters, that the text model fits in about 1 GB at 4-bit, and that it has a 256K context window and can be fine-tuned on a single GPU.

GitHub Copilot Fusion orchestrates Anthropic and OpenAI models to balance performance and cost

GitHub's Copilot Fusion is a runtime orchestration layer that picks among models including Claude Opus 5.5, Claude Sonnet 5.5, GPT-6 Astra and GPT-6 Sol per task. AA benchmarked its max setting in Copilot CLI on Coding Agent Index v2.0: it costs $5.59 per task against $11.42 for Claude Code with Opus 5.5 (max), uses about half the tokens (7.2M per task), and sits two points below Opus 5.5 overall. Incident report · Oct 26 · 3 days old
Cross-request KV cache exposure in the GLM-5.3 Workers AI model, and our remediation with SGLang

Cloudflare reports that between Aug 27 and Sep 9, 155 responses from its GLM-5.3 Workers AI deployment to prompts longer than 681,280 tokens contained data from other customers' recent requests, and says it found no evidence of deliberate exploitation. Two causes overlapped: the model was deployed with a 1,048,576-token context window while the prefill GPUs' KV cache pool held only 681,280 tokens, and an SGLang bug in disaggregated prefill/decode mode substituted a one-token placeholder for over-length prompts instead of aborting them, so the decode node attended over stale cache pages from earlier requests.

The fix enlarged the pool to about 2.04 million tokens and patched the rejection path; the changes went upstream to SGLang in a coordinated disclosure.

Flip Tech Watch · Oct 28
Runtime model orchestration for cost

AA's Copilot Fusion results show a router over several frontier models reaching near-top scores at roughly half the cost and half the tokens of a single top model on coding tasks.

Flip angle: the same pattern applies to call handling: send simple intents (order status, policy lookups) to a cheaper model and reserve the strongest model for multi-step returns and exceptions. The first test should replay escalated calls through a two-tier router and compare automation rate, escalation reasons and cost per call. Coding benchmarks do not transfer directly to phone support, and routing adds a decision step to every turn's latency.

Flip Tech Watch · Oct 26
Tenant isolation checks for self-hosted long-context serving

Cloudflare's incident (above) came from a context window larger than the KV cache pool combined with an engine bug on the rejection path.

Flip angle: any shared inference stack serving multiple clients' call transcripts should assert that the configured context length fits the KV pool and run canary-marker tests, where a unique string in one tenant's prompt must never appear in another's output. Whether this applies depends on whether Flip's serving path uses a disaggregated prefill/decode engine at all.

🧠 Today's Lesson
Disaggregated prefill and decode: why the KV cache has to travel between GPUs

Serving an LLM request has two phases with opposite bottlenecks. Prefill processes the whole prompt in one parallel pass and is compute-bound; decode generates one token at a time, rereading the KV cache each step, and is memory-bandwidth-bound. Running both on the same GPUs makes them interfere: a long prefill stalls other users' token streams, and decode leaves compute idle.

Disaggregation splits them into separate pools. Prefill GPUs build the KV cache for a prompt, then transfer it over a fast interconnect to a decode GPU, which continues generating. Each pool can be sized and tuned for its own bottleneck, which usually improves time-to-first-token and keeps inter-token latency steadier under load.

The cost is a new correctness contract. The decode node receives a "transfer complete" signal and trusts that the pages it reserved now hold this request's prompt. If prefill sends less than expected, the remaining pages still contain whatever the previous occupant left, and the model happily attends over them. That is the failure mode Cloudflare described: a placeholder cache transferred in place of an over-length prompt. The defences are structural: make sure the context limit fits the pool, reject bad requests before any allocation or transfer, and have decode verify that the token count received matches the count reserved.
