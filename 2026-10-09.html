Inference · Show HN · Oct 9
Narwhal: an open-source serving layer that moves GPUs between prefill and decode in seconds

Narwhal treats the prefill/decode split as a runtime scheduling decision rather than a provisioning one. Every engine can serve either phase, and a controller reassigns roles while weights stay loaded, so re-splitting a fleet is "one label write" instead of minutes of draining. The scheduling core is an independent implementation of the Arrow paper (arXiv 2505.11916), extended with request journaling, health-checked ejection and a warm-standby scheduler.

The author reports 157,823 requests and 1.99B tokens on a live six-node fleet with zero false ejections. Treat that as a claim for now: the comparison study is unpublished, the repo shows a single commit, and the HN post has only a couple of points. Apache-2.0. The design is the interesting part, whether or not anyone runs it.

Opinion · HN · Oct 9
"--help on your CLI is all you need for LLM context until you don't"

Geoffrey Huntley argues that whether a developer tool wins with coding agents depends on whether models already know it from training: the GitHub CLI works with no skills or MCP server because it is in the weights. Newer tools can climb the same ladder by shipping a strong CLI with carefully tuned --help output, publishing docs that an agent can use after one web search, and getting those docs into future training runs.

Anthropic Cyber Mission: free OSS Scanner and a Critical Infrastructure Defense Program

OSS Scanner is a free, opt-in service that gives enrolled open-source projects periodic vulnerability scans from Anthropic's strongest models. Reports include a proof of concept, an explanation and a suggested fix where available, and they go out without human review. Anthropic says it expects a true-positive rate above 90%, which is its own target rather than a measured result.

The Critical Infrastructure Defense Program gives operational-technology security providers (power, water, transport, government systems) access to frontier models, on-site engineers and threat research. Founding partners include CrowdStrike, Palo Alto Networks, Dragos, Accenture, Deloitte and Rockwell Automation.

vLLM v0.31.0: weight preload for fast restarts, draft-model spec decoding on Model Runner V2

717 commits from 307 contributors. vllm preload starts a daemon that keeps post-quantized weights in GPU memory across engine restarts. Draft-model speculative decoding and custom logits processors now run on Model Runner V2. FlashMLA with a compressed NVFP4 KV cache is the SM100 default for DeepSeek-V4.1-Flash, and a new --max-num-active-seqs flag caps running requests independently of max_num_seqs.

Breaking changes: tokenizer_mode="slow" is removed, and per-request multimodal kwargs are rejected unless --trust-request-mm-kwargs is set.

🧠 Today's Lesson
Disaggregated serving: why split prefill from decode?

An LLM request has two phases with opposite hardware profiles. Prefill processes the whole prompt in parallel: it is compute-bound and sets time-to-first-token (TTFT). Decode generates one token at a time: it is memory-bandwidth-bound, because every step re-reads the weights and the KV cache, and it sets per-token latency.

On a single GPU pool the two interfere. A long prefill stalls running decodes, which shows up as stuttering output, and chunked prefill only softens the effect. Disaggregation runs prefill on one set of GPUs and decode on another, shipping the KV cache between them over a fast interconnect, so each pool can be tuned and scaled to its own SLO.

The costs are the KV transfer and, harder, the ratio. If traffic shifts toward longer prompts, the prefill pool is too small while decode GPUs sit idle. That is the problem Narwhal targets: let every engine play either role and rebalance live instead of re-provisioning. The vLLM 0.31 scheduling flags above attack the same interference inside one pool. Rule of thumb: disaggregate when prompts are long and latency SLOs are tight; otherwise chunked prefill on a unified pool is simpler.
