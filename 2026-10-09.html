What's Hot Right Now

Narwhal: move GPUs between prefill and decode in seconds

Show HN, Oct 9 · Apache-2.0 · early (2 points on HN) · all claims are the author's own

An open-source serving framework for disaggregated inference that treats the prefill/decode split as a runtime scheduling decision. Every engine can serve either phase, and a controller reassigns roles while weights stay loaded, so re-splitting a fleet is "one label write" instead of minutes of draining. Built on the Arrow paper (arXiv 2505.11916). The author reports 157,823 requests / 1.99B tokens on a six-node fleet with zero false ejections, but the comparison study is unpublished and the repo shows a single commit. Worth a read of the design even if you don't run it (see today's lesson).

Today's Lesson

Disaggregated serving: why split prefill from decode?

An LLM request has two phases with opposite hardware profiles. Prefill processes the whole prompt in parallel: compute-bound, big matmuls, determines time-to-first-token (TTFT). Decode generates one token at a time: memory-bandwidth-bound (reading weights and the KV cache each step), determines per-token latency.

On one GPU pool they interfere: a long prefill stalls running decodes (visible stutter), and chunked prefill only softens that. Disaggregation runs prefill on one set of GPUs and decode on another, shipping the KV cache between them over a fast interconnect. Each pool is then tuned (and scaled) for its own SLO: TTFT for prefill, inter-token latency for decode.

The cost is the KV transfer and, harder, the ratio. If traffic shifts to longer prompts, your prefill pool is too small and decode GPUs idle. That is the problem Narwhal's pitch targets: make each engine able to play either role and rebalance live, rather than re-provisioning. The vLLM 0.31 flags above (--max-num-active-seqs, adaptive long-prefill threshold) attack the same interference inside a single pool. Rule of thumb: disaggregate when prompts are long and latency SLOs are tight; otherwise chunked prefill on a unified pool is simpler.
