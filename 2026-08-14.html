🔥 What's Hot Right Now
Encrypted reasoning traces were never actually private — and 182 credentials leaked from public logs
The Hacker News·Aug 12·Security

ELLIS Institute researchers scraped 6,708 public agent trajectory logs from GitHub and Hugging Face, decoded 315,320 reasoning blocks, and recovered 182 credentials — API keys, passwords, access tokens — from real user sessions. The root cause: OpenAI, Anthropic, and Google all used a single global encryption key for their encrypted CoT tokens, meaning a reasoning block from one session could be replayed into any other, and even handed to a weaker model in the same family to make it dump the hidden content.

All three providers have patched the extraction attack. The catch: the patch is server-side. Every reasoning block already sitting in a public repo or shared log is still decodable by anyone who ran the attack during the July testing window. Action item: audit any agent logs you've shared or published and strip encrypted reasoning fields before they go anywhere.

📖 Today's Lesson
Chunked Prefill: how to stop one long prompt from freezing everyone else out

When a new request arrives at an inference server, the engine has to process the entire prompt before it can emit a single output token. For a 1M-token context window like DeepSeek V4 Pro or Gemini Flash, that prefill phase can take several seconds — and while it's running, it monopolizes GPU compute, blocking decode (token generation) for every other request in the batch. This is the prefill-vs-decode resource contention problem.

Chunked prefill solves this by breaking the long prompt into fixed-size chunks (typically 512–4096 tokens) and interleaving them with decode work across scheduler ticks. Each tick, the scheduler runs one chunk of prefill and a batch of decodes together. The long prompt still finishes eventually, but in the meantime other users' generation continues at near-normal speed.

The tradeoff: chunked prefill adds latency to the TTFT (time-to-first-token) of the long request — you don't start generating until all chunks are prefilled — but dramatically improves fairness and tail latency for concurrent users. SGLang and vLLM both support chunked prefill; it's usually controlled by a max_num_batched_tokens or chunk_prefill_size parameter. Worth tuning if you're serving a mix of short interactive queries and long-context agent calls at the same time.
