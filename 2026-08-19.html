🔥 What's Hot Right Now
Four 2017 V100s match an RTX 5090 running Qwen 3.8 NVFP4 — via a software FP4 translator kernel
The most technically impressive post on r/LocalLLaMA today. NVFP4 was purpose-built for Blackwell silicon — V100s have no native FP4 or FP8 tensor cores. A developer wrote QPN, a kernel that keeps the model compressed in HBM and translates each fragment into FP16 on-the-fly during the read, fast enough to hit 679 GB/s effective bandwidth on 879 GB/s cards. Result: 4× V100-SXM2-16GB at ~A$600 total card cost decoding at 219 tok/s single-request, vs. one RTX 5090 at 215 tok/s — statistical parity. The trick: Volta's tensor instruction works on 8-row tiles, and a k=7 speculative verification round maps neatly onto those 8 rows, so deeper MTP speculation is unusually cheap. This isn't a GEMM screenshot — it's a full OpenAI-compatible serving endpoint with tensor parallelism, flash attention, and CUDA Graphs. The lesson buried in the methodology: at long context (~65K tokens), k=7 MTP actually hurts; drop to k=3 and throughput goes from 55 → 76 tok/s. Prefill is not parity — NInfer is ~4× faster there.

Qwen3.8-27B is excellent — but it defaults to wildly overthinking things
Simon Willison's Aug 16 benchmark: generating an SVG of a pelican on a bicycle took 21 minutes and 22,276 reasoning tokens to produce 3,223 output tokens. Default reasoning_effort: xhigh is the culprit — Alibaba set "think a lot" as the default and Artificial Analysis measured 160M output tokens across their test suite vs. a 43M median for comparable models. The fix is just setting enable_thinking=False or lower effort for non-reasoning tasks. His follow-up on Aug 17: the model still scores 52 on the Artificial Analysis Intelligence Index, matching GPT-5.6 Luna — the quality is real, the defaults are just wrong for most use cases.

📖 Today's Lesson
PagedAttention: how vLLM treats GPU memory like virtual RAM to eliminate KV cache fragmentation

Every token a model generates needs its attention keys and values stored for the rest of the sequence — that's the KV cache. Before vLLM, inference servers pre-allocated a fixed contiguous block of GPU memory per request at arrival time. Problem: you don't know response length, so you over-allocate. And as requests finish at different times, memory becomes Swiss cheese — gaps that can't fit new requests. GPU utilisation craters under concurrent load.

PagedAttention borrows the OS solution to the same problem in RAM: virtual memory with paging. Instead of one big contiguous block, the KV cache is divided into fixed-size pages (typically 16 tokens of keys + values per page). A page table maps each request's logical token positions to physical GPU memory pages that can live anywhere — non-contiguous is fine. New pages are allocated on demand as generation grows.

The results: near-zero fragmentation waste, the ability to serve far more concurrent requests on the same GPU, and a natural basis for prefix sharing — multiple requests with the same system prompt can point at the same physical pages without copying. This is why prefix caching (covered Aug 7) is cheap in vLLM: the pages already exist, you just add another pointer in the page table.

This also connects directly to today's V100 story: v100-skinny builds on vLLM's serving architecture with its PagedAttention scheduler and then adds the QPN2/QPN8 kernels on top. The memory efficiency isn't incidental — it's what makes four 16GB cards viable for a 27B model at all. PagedAttention is the reason vLLM became the default for multi-user production serving; on typical workloads it cuts KV cache memory waste by 55–75%, which translates directly to throughput at the same hardware cost.
