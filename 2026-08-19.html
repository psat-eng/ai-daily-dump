Qwen3.8-27B thinks too hard — and the community is figuring out how to stop it
The biggest local-AI story of the week isn't the benchmarks, it's the behaviour: Qwen3.8-27B defaults to reasoning_effort: xhigh, which means it burns through your context window thinking before it replies. Simon Willison clocked 22,276 reasoning tokens to produce 3,223 output tokens for a simple SVG task — 21 minutes on his hardware. The fix is straightforward (set reasoning_effort: none or low for non-reasoning tasks) but it's not the default, and that's catching people out. VentureBeat called it "frontier-class coding agents locally" — true, but read the fine print on token burn.

📖 Today's Lesson
PagedAttention: how vLLM treats GPU memory like virtual RAM to eliminate KV cache fragmentation

Every token a model generates needs its attention keys and values cached for the rest of the sequence — the KV cache. Before vLLM, inference servers pre-allocated a fixed contiguous block of GPU memory for each request's KV cache at arrival time. The problem: you don't know how long the response will be, so you over-allocate. And as requests finish at different times, memory becomes Swiss cheese — small gaps that can't fit new requests. GPU utilisation craters.

PagedAttention borrows the solution OS kernels have used for RAM since the 1960s: virtual memory with paging. Instead of one big contiguous block, the KV cache is divided into fixed-size pages (typically 16 tokens worth of keys and values per page). A page table maps each request's logical token positions to physical GPU memory pages, which can be anywhere in memory — non-contiguous is fine. New pages are allocated on demand, one at a time, as the generation grows.

The results: near-zero memory waste from fragmentation, the ability to serve many more concurrent requests on the same GPU, and a natural mechanism for prefix sharing — multiple requests that share a common prefix (e.g. a system prompt) can point to the same physical memory pages without copying. This is why prefix caching (covered Aug 7) is so cheap in vLLM: the pages are already there; you just add another pointer.

PagedAttention is the core reason vLLM became the de-facto standard for multi-user serving. The memory saving isn't marginal — on typical workloads vLLM reports 55–75% reduction in KV cache memory waste, translating directly into throughput at the same hardware cost.
