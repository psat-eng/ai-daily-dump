Mini-AGI: continual learning model that trains from scratch on 8GB VRAM
A genuinely interesting toy project on HN today (211 pts). The model is a byte-level LM that stores weights on disk and pages them to GPU as needed, so parameter count is bounded by disk space, not VRAM. It trains continuously — one gradient step per chunk read — and there's no separate fine-tuning regime: reading and training are the same event. Anti-catastrophic-forgetting is built-in via a prune/grow scheme. The author is explicit this is a small experiment, not a production system, but the architecture ideas are worth a look for anyone thinking about long-lived edge inference.

Heretic: fully automated censorship removal for open LLMs
Landed on HN today with 150 points. Heretic strips safety alignment from transformer models without retraining — it uses directional ablation (similar to what the "abliteration" technique does) combined with TPE-based parameter search via Optuna to find optimal removal parameters automatically. No expensive RLHF pass needed. The project has been around since March but seems to have shipped a new version; the HN thread is active. Worth understanding how this works even if you're not deploying it — the same directional-activation techniques are used legitimately in interpretability research.

💡 Today's Lesson
Non-Autoregressive Models: What "System 1" Inference Actually Means (and Why It's Not Just Marketing)

Every LLM you've worked with is autoregressive: it generates token n+1 by conditioning on all previous tokens, one at a time. This is beautifully general — it can produce any sequence — but it's serially bottlenecked. Token 50 cannot be computed until token 49 is done. Your throughput ceiling is roughly 1 / (time_per_token × sequence_length).

Non-autoregressive (NAR) models break this constraint by producing all output positions in a single parallel forward pass. The catch: if you don't know what token 49 is, you can't condition token 50 on it. NAR models get around this in different ways — masked diffusion (fill in [MASK] tokens simultaneously), continuous-time diffusion in embedding space, or — like TypeSafe's Jev — simply restricting the output space to typed decisions rather than open-ended text. Jev doesn't need to "write" anything; it classifies into a fixed schema of actions/decisions, which means conditional dependencies between output positions are trivially resolvable upfront.

The tradeoff is expressiveness. NAR models excel at high-volume, repeated decisions over known output spaces — routing, classification, structured extraction, game actions. They are not competitive with autoregressive LLMs for open-ended generation, and tend to require output-schema constraints at design time.

The "System 1 / System 2" framing TypeSafe uses maps loosely to Kahneman's cognitive model: fast-pattern-matching (System 1) vs. deliberate reasoning (System 2). The analogy is imperfect, but it captures a real engineering point — many inference calls inside a production loop don't need full generative reasoning, just fast structured outputs. A 193× speedup makes sense in those narrow cases. The interesting question for you as an inference engineer: which parts of your agent's call graph could be replaced with a NAR decision model without loss of quality?
