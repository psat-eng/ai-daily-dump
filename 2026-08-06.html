📦 New Releases & Updates
Zero-Mem: agent memory with zero LLM token cost
arXiv HN — 92pts Aug 5, 2026

Fresh paper (arXiv:2607.29377) that eliminates LLM calls from memory operations entirely. Instead of using an LLM to write/retrieve memories, Zero-Mem uses encoder-only models organized into an entity-context graph (for cross-session connections) and a temporal hierarchy (for conversational locality). Result: 57.6% faster memory operations than the fastest existing baseline, competitive QA accuracy. Directly relevant if you're building long-running agents and burning tokens on memory management.

AMD acquires Taalas — the startup that etches AI models directly into silicon
Hardware CNBC — Aug 6, 2026

Taalas (Toronto, founded 2023) came out of stealth in February with a demo chip doing 16,000+ tokens/sec per user on Llama3.1-8B — multiples of what current-gen AMD/Nvidia hardware achieves. Their approach: don't build a general-purpose accelerator, bake a specific model's weight layout directly into the silicon. AMD's acquisition folds this specialized inference expertise into its accelerator roadmap. This is the same play as Nvidia's ~$20B Groq buy but from the other direction. Deal expected to close Q4, terms undisclosed.

Worth watching: model-specific silicon is a bet that a small set of dominant models (Llama-family, Qwen, etc.) will be stable enough to warrant custom chips. If the model landscape consolidates, this approach wins big on cost and throughput.

How OpenAI built GPT-Live: full-duplex voice AI in six months
Engineering Blog OpenAI — Aug 3, 2026

This is a genuinely good infrastructure post. GPT-Live removes the turn detector from the audio path entirely — the voice model is full-duplex (listens and speaks simultaneously). Deeper reasoning delegates async to GPT-5.5 without blocking the audio stream. The engineering highlights: (1) WARP protocol — their new open WebRTC extension that cuts media+data startup from 6 network round-trips to 1, now being proposed through IETF; (2) seamless context compaction — when the KV cache grows too large, they warm a new model instance in parallel, prefill it, then hot-swap without any audio gap; (3) the media frontend is rewritten in Go (from Python asyncio), with p95 matching the old system's p50; (4) they shadow-tested on real production traffic before launch, which revealed that CPU stream handlers — not GPUs — were the actual bottleneck under voice load.

If you're building any kind of streaming AI system, the architecture section on separating the media fast-path from application/business logic is worth reading carefully.

📖 Today's Lesson
Prefix Caching: why your system prompt shouldn't cost tokens twice

Every time you send a request to an LLM, the model has to compute attention over every token in the prompt — including the system prompt that's identical across every single call. Prefix caching is the fix: the inference engine computes the KV (key-value) cache for a shared prefix once, stores it, and reuses it on subsequent requests that start with the same prefix. The KV cache is the materialized attention state — the intermediate tensor that captures what each token "knows" about every prior token. Reusing it skips all the compute for those tokens.

In practice, a 2,000-token system prompt that's cached hits the model as if it's a 0-token prefix for all subsequent calls. This collapses Time-to-First-Token (TTFT) dramatically, especially for short follow-up turns. vLLM calls this prefix_caching; SGLang calls it RadixAttention (it uses a radix tree to cache arbitrary shared prefixes, not just a fixed system prompt). Anthropic's prompt caching product is the API-layer version of the same idea.

The tricky part is cache invalidation: the prefix must match exactly — a single character difference creates a cache miss. This means you should keep your system prompt stable across a session and put variable content (user data, context) after the static prefix. In multi-tenant deployments, prefix caching also reduces GPU memory pressure because the same KV tensors are shared across users hitting the same model config. The result: lower cost and lower latency, for free, just by structuring your prompts correctly.
