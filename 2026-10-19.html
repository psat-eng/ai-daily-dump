Mistral's Timestral: a 209M-parameter forecasting model that runs on CPU and tops GIFT-Eval, TIME and fev-bench

Mistral's first time-series foundation model family comes in four sizes (5M, 28M, 123M, 209M parameters) under a modified MIT licence, with a 32,768-step context and 21-quantile probabilistic output. Mistral says the 209M model ranks first among pretrained zero-shot models on all three public benchmarks while using about two-thirds of the parameters of the previous best. It reports that the 28M model beats Chronos-2, roughly four times larger, on GIFT-Eval and TIME.

The serving story is the unusual part: no GPU is needed. On an 8-thread server CPU, a one-day-ahead forecast from three weeks of 15-minute history takes 10 ms with the 5M model and 140 ms with the 209M model. It handles multivariate targets plus past-only and known-future covariates, including categorical ones. Training data was mostly synthetic, with a "decoupled horizon" scheme in which learned forecast tokens read the full history instead of masking it. A technical report is promised; the benchmark claims are Mistral's own submissions.

Open Source · Oct 2026, Show HN today
Qwen3-4B with the AI writing tics trained out, fine-tuned on a MacBook Air

Erik Kannike distilled Qwen3-4B-Instruct-2507 into a model that avoids em dashes, "not X, but Y" constructions and rule-of-three lists. A teacher model answered 288 prompts, only answers passing a style score and task-fit checks were kept, and a rank-16 LoRA was trained on them in three rounds of one to three hours each on an M2 MacBook Air. The author's regex-based slop score drops from 121 to 12.5 per 1,000 words (human writing usually lands under 15), em dashes fall from 20.5 to zero, and a 30-question factual check stays at 30 of 30.

The caveats are in the post itself: it is one author, the detector is self-built, no blind reader test has been run, and the training data was filtered on the same checks that are reported. Output still invents names and runs long. Weights are on Hugging Face as erikkannike/qwen3-4b-deslop-v4, with a Q4_K_M GGUF (2.5 GB) for Ollama.

CPU-only probabilistic forecasting for call volume and anomaly alerts

Timestral's smallest models (5M and 28M parameters) forecast with known-future covariates such as day of week and scheduled events, and return 21 quantiles rather than a single number. Mistral reports 10 ms per forecast on an 8-thread CPU for the 5M model.

Flip angle: per-client call-volume forecasting and spike alerts (promotions, shipping delays, holiday returns) could run beside the existing stack with no GPU, and the quantile output maps naturally to staffing and escalation-capacity thresholds. What to test first: zero-shot accuracy on a few clients' hourly intent volumes against a simple seasonal baseline. The licence is a modified MIT, so terms need reading before production use.

🧠 Today's Lesson
Prompt caching: why one changed token near the top invalidates everything after it

Prompt caching stores the KV cache of a prompt prefix so the next request that begins with the same tokens skips recomputing it. Cached input is billed far cheaper, which is why M3.1 Flash lists cached input at a tenth of the normal input price.

The catch is that attention is causal: every token's key and value depend on all tokens before it. A cache hit therefore requires an exact, token-for-token match of the prefix. Change one token at position 50 and the cache for positions 51 onward is useless, because those entries were computed with the old token in their context.

That rule explains most cache misses in agent loops. A timestamp or request ID in the system prompt, tool definitions reordered between calls, a JSON dump with unstable key order, or an edit to an earlier message all break the prefix. The fix is structural: put stable content first (system prompt, tool schemas, long documents), append volatile content last, and never rewrite history.

This is also why per-request logging at a proxy pays off. Recording cached versus uncached input tokens per call turns a mystery bill into a diff of two prompts, showing exactly where the first mismatched token sits. Many providers also expire entries after minutes of idle time, so bursty traffic can miss even with identical prompts.
