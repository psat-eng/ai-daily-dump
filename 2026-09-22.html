Inference Engine

A big release. The unified radix tree now records branching points, so requests sharing a long system prompt reuse far more of the cache. On DeepSeek-V4-Flash, token hit rate goes 43.8% → 60.8% and TTFT drops 1.57s → 1.07s. That's a real gain with zero prompt engineering.

RL rollouts get a dedicated path: sampling masks with overlap scheduling raise decode throughput on Qwen3-8B by 17% at batch 1 and 52% at batch 64. New --sampling-mask-max-tokens flag controls capacity. New models: GLM-5.3-Flash, Qwen3.8-Flash-Next, Tencent Hy4-Preview, K2 Horizon, plus Mamba 1/2 state-space support. Breaking: no CUDA 12 wheels — pin v0.5.19 if you're not on CUDA 12.4+.

💡 Today's Lesson
MoE Expert Offloading: How to Run a 200B Model on a Box That Can't Hold It

Mixture-of-Experts (MoE) models like DeepSeek-V4 and Qwen3.8 are structurally appealing for inference: only a small subset of "experts" activate per token, so compute per token stays low even as total parameter count is huge. The catch is that all those expert weights still have to live somewhere — and a 200B MoE model can have 160–180B of that mass sitting in expert layers alone.

The problem: On a server with, say, 80GB of GPU VRAM, most of a large MoE doesn't fit. Naively, you'd need to parallelize across many GPUs or use a smaller model. Expert offloading offers a third path: keep only the most-frequently-used experts in GPU VRAM, and cache the rest in CPU pinned memory (page-locked RAM that the GPU can DMA from without going through the OS).

How it works: A router module (the part of MoE that decides which experts handle each token) predicts which experts will be needed for an upcoming batch. The offloading layer pre-fetches those expert weights from CPU to GPU asynchronously — overlapping the data transfer with the computation of the previous layer. If your batch is big enough and your prediction is accurate, the GPU never stalls waiting for weights. This is sometimes called "prefetch-and-compute overlap."

The tradeoff space: Pinned memory transfer bandwidth (PCIe 5.0 saturates around 60–64 GB/s bidirectional) is roughly 10× slower than GPU HBM bandwidth (~3.3 TB/s on H100). So expert offloading works when: (a) experts are large relative to per-token compute — true for MoE; (b) batch sizes are big enough to amortize the transfer; (c) the router's expert predictions are accurate and made early enough. It breaks down at small batch sizes or when expert selection is unpredictable. That's why vLLM's RFC frames this as "incremental" — only cold/rarely-used experts get offloaded, not the whole model.

The practical upshot: if you're running a large MoE on a single node with 1–2 GPUs and the model doesn't quite fit, expert offloading can close the gap — at the cost of some throughput. Worth profiling before you scale to more cards.
