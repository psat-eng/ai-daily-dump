Aug 17–18 · cursor.com

Copilot Autofix introduced a shell-injection bug — and it was exploited
Aug 17 · Wiz

📖 Today's Lesson
Flash Attention: why fitting attention in SRAM rather than HBM made long contexts practical

Every transformer layer does the same expensive operation: it computes attention scores between every pair of tokens, producing a matrix that's quadratic in sequence length. The naive implementation writes those intermediate matrices to GPU high-bandwidth memory (HBM) repeatedly — once when computed, again when read back. HBM is fast but it's off-chip, and bandwidth to it is the actual bottleneck in most attention workloads.

Flash Attention (Dao et al., 2022, extended to v2 and v3 since) solves this by tiling the attention computation so the entire working set for each tile fits in SRAM — the on-chip memory that's ~10–100× faster than HBM but tiny (a few MB vs 80 GB). Rather than materializing the full N×N attention matrix, it processes it in blocks, accumulating the softmax numerically in a running fashion using the log-sum-exp trick. The result is identical to standard attention, but with dramatically fewer HBM reads and writes.

The practical payoff: Flash Attention is roughly 2–4× faster than naive attention on long sequences, uses O(N) instead of O(N²) memory, and made 100K–1M token context windows economically viable. Almost every production inference engine (vLLM, SGLang, llama.cpp, TensorRT-LLM) uses it by default. When you see "context window extended to 1M tokens," Flash Attention is a major reason that's possible at all — without it, the intermediate attention matrices for long sequences would simply not fit in GPU memory.
