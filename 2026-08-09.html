Jeff Dean, Sanjay Ghemawat, Quoc Le & Oriol Vinyals all leave Google to found Discovery Loop
The four Google/DeepMind legends announced Discovery Loop on August 5 — a Palo Alto startup whose mission is to automate the scientific process itself. The core idea: instead of humans running experiments in series, their AI systems run thousands in parallel, propose next experiments, learn from results, and iterate recursively. They're starting by automating ML research (acting as their own first customer) and then pointing it at medicine, materials, and clean energy. Funded by Radical Ventures and Khosla co-leading, with Lightspeed, Kleiner Perkins, Doerr Capital, and Alphabet also in. The Latent Space newsletter had a detailed breakdown of the internal Google dynamics that precipitated this — Demis chairs DeepMind now, Koray moves to SVP.

Anthropic confirms in-house chip team — targeting ~50% inference cost cuts for Claude
Anthropic officially confirmed on August 5 that it's building a silicon design team, hiring senior chip engineers at up to $485K. The stated goal is co-designing chips and Claude models together — optimizing the silicon to the specific sparsity patterns, attention variants, and memory access patterns of Claude rather than fitting Claude to general-purpose hardware. 📖 Today's Lesson
Continuous Batching: how inference servers serve 100 users without wasting a GPU cycle

Early LLM serving was embarrassingly wasteful. If you had a batch of 8 requests and one finished early, the GPU sat idle on that slot until every request finished — because the next batch couldn't start until the current one was done. For requests with wildly different output lengths (some 10 tokens, some 2,000), the average GPU utilization was terrible.

Continuous batching (also called "iteration-level scheduling" or "in-flight batching") solves this. Instead of waiting for a full batch to complete, the scheduler operates at the granularity of a single decode step. After each token is generated, it checks whether any slot finished — and immediately slots in a new request from the queue. The result: the GPU is almost always fully occupied, and a short request doesn't have to wait behind a long one.

vLLM and SGLang both implement this. The key enabler is PagedAttention — managing KV cache memory in non-contiguous pages so new requests can be inserted without requiring a full memory reallocation. Without paged memory management, continuous batching is hard to implement efficiently because you can't predict ahead of time how much KV cache each request will need.

In practice, this is why modern inference servers can saturate a GPU at hundreds of concurrent requests, while a naïve serving loop on the same hardware would bottleneck at a handful. If you're evaluating inference frameworks, ask specifically about their batching scheduler — it's often the single biggest determinant of real-world throughput.
