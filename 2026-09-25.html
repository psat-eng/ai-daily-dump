🔥 What's Hot Right Now
Tool · HN today, climbing
Jevmem: automatic project memory for Claude Code, built on last week's Jev "decision model"

Jevmem watches your Claude Code / Cursor / Codex sessions and auto-maintains a JEVMEM.md file, using TypeSafe AI's Jev (the "System One" decision model Simon Willison wrote up on Sep 21) to score which turns are worth remembering — constraints, bugs, todos, preferences. Reversed decisions get marked superseded rather than deleted. It shipped v0.4.5 today (MCP tool annotations, a vitest security bump, cleaner saved lines) and hit the HN front page within the hour.

The comments are the real content. Top complaint: the AI-written README "includes every detail... and still doesn't communicate the essence of the project" — several people couldn't tell what problem it solves that a hand-written CLAUDE.md doesn't. Others flagged that every chat turn and memory file round-trips through TypeSafe's servers, and that keeping superseded entries around risks confusing a non-deterministic model about which guidance is current. Some found it genuinely useful anyway. Worth reading before you reach for it on a client project.

Released Sep 23
Ollama 0.34.4: structured outputs on thinking models now finish in a single pass

Previously, a thinking model producing structured JSON output paid for two passes — one to think, one to conform to the schema. 0.34.4 collapses that into one pass, which is a direct latency win for anyone using function-calling or JSON mode on a reasoning model locally. Also in this release: a fix for intermittent "model not found" errors against large local model libraries, plus more Apple Silicon / MLX performance tuning for Qwen and Gemma. Small release, but a real one if you're serving thinking models through Ollama.

Legal · Sep 25
Federal appeals court sides with the Pentagon, keeps Anthropic's "supply chain risk" label in place

The DC Circuit ruled 2-1 that the Defense Department can keep Claude models out of its systems and off DoD work, rejecting Anthropic's challenge to the designation Trump and then-Defense Secretary Hegseth applied back in February. Judge Gregory Katsas wrote that "the Department reasonably feared that Anthropic might manipulate Claude's design to prevent it from performing national-security functions." Anthropic says it "respectfully disagrees" and is weighing further review. Notably separate from the California ruling this summer that found the Pentagon acted illegally when it punished Anthropic for criticizing government AI policy — two different fights, two different outcomes.

Infra & Policy · Sep 24
The NSA is spending billions a year just to test frontier AI models for security holes

The NSA's Artificial Intelligence Security Center has been red-teaming frontier models since a string of high-profile agent-hacking incidents this year, and classified budget estimates put the annual cost in the billions — dwarfing the ~$20M/year the CBO estimated for a comparable bipartisan House oversight proposal. Most of the spend is compute (amid ongoing chip shortages) and evaluation talent, some of which reportedly commands compensation in the hundreds of millions. It's reviving a real policy question: should frontier labs fund their own third-party evals through an assessment fee, rather than taxpayers footing it?

🧠 Today's Lesson
Agent Memory: Why Compaction Alone Isn't Enough (and What Jevmem's Critics Got Right)

Long agent sessions run out of context budget, so most harnesses periodically compact: summarize everything so far into a shorter blob and keep going with the freed-up tokens. This is lossy by construction — a constraint the agent agreed to five turns ago can quietly vanish from the summary — and it has a subtler failure mode too: a compaction summary is itself just another LLM completion, which means it can drift from what actually happened, or (as researchers have documented) even get hijacked into injecting instructions that survive into the next turn.

External memory files — a CLAUDE.md, an AGENTS.md, or an auto-maintained JEVMEM.md like today's tool — sidestep the forgetting problem by writing durable facts to disk instead of hoping they survive the next summary. But today's HN thread on Jevmem surfaced the real cost: an automatically-written memory file that never deletes anything just relocates the token-budget problem from "what do we summarize away" to "what do we retrieve back in." Keeping every superseded decision as a footnote sounds safer than silently deleting it, but it also means a non-deterministic model has to disambiguate old guidance from current guidance every single time it reads the file.

Why you care: this is the same lesson RAG systems learned the hard way — write freely, retrieve narrowly. Store everything if storage is cheap, but decide what actually enters context per turn by recency and relevance, not by appending the whole file. That distinction is what separates a memory system from a growing log file with delusions of memory.
